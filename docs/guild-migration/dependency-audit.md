# Guild dependency audit

The starting app had two readers for the guild asset. `GuildsService.GetAllAsync` loaded the full catalogue, expanded specialisation choice sets and cloned ability definitions for all guild tiers. `GetMiracleSearchAsync` read the same asset again for the miracle search. Neither reader understood the workspace's version 2 envelope. The full reader threw on the numeric schema version and the miracle reader treated the envelope as a single guild.

| Boundary | Dependencies and callers |
| --- | --- |
| Packaged rules | The MAUI project includes the raw resources automatically. Guild definitions use the shared ability and choice-set indexes in `SpecialisationDefinitionRepository`. Evolution searches and ability detail lookups also consume the specialisation catalogue. Miracles, spells, evocations and neuronics each have their own loaders and database-backed lookup paths. |
| Eligibility | Guild availability is evaluated by `GuildsVm` and the existing `RuleTreeEvaluator`. Progression thresholds come from `GuildBenefitTierService` and include race-specific exceptions. Character creation and advancement use `CharacterCreationDataService` and `AdvanceCharacterDataProvider` for reference reads. |
| Guild results | Previously `CharacterBuilderVm` and `GuildsVm` each walked the tiers and selected options. The builder consolidated updates across all sources by names and update keys. The refactor routes character grants and structured choices through `GuildCharacterBenefitResolver` and the pure `GuildGrantResolver`. The catalogue remains available for static guild detail and search. |
| Character storage | `LiteDbService` persists guild names in `guilds_json` and the full `CharacterDraft` in the account workspace's draft snapshot. The legacy choice dictionary exists in that snapshot. Explicit mappings convert its positional values to stable option IDs and retain the raw values for review. Adventure selections use transient state and a persisted migration marker records values adopted once. |
| Applied mechanics | The character builder contributes effective abilities to life, armour, resistance and innate calculations. The interactive battleboard and spreadsheet export use shared life, resistance, item and innate services. The PDF document service renders the exported workbook. Per-source armour stacking uses `ArmourBonusResolver`, which excludes conditional and activated guild effects from unconditional totals. |
| Ability information | Guild rows delegate to the common detail lookup and retain inline definitions. The rule catalogue and resolver supply related rules on request. Ability definitions and account-specific lookup results have different cache lifetimes. Packaged indexes can be shared, while member-dependent lookup caches must invalidate on account switches. |

The prior `Key` and `AbilityRef` could be aliases for one definition or differ because one was a grant-specific legacy token. The dedicated grant identity identifies the award to upgrade, even when it shares a canonical ability with another source. `UpdateKey` remains relevant to non-guild legacy updates and battleboard ownership and lookup fallbacks. `ChoiceSetRef` and `ChoiceSetRefs` reference external templates and remain in use by specialisation and multipath features. The C# audit found no runtime consumer for `CheckKey`.

Saved snapshots can contain derived values calculated during an earlier session. The wallet's interactive and export actions, and the battleboard character list, now use the character builder to refresh those values and resolve pending guild selections after loading. Review-page actions use the live builder. The snapshot schema still retains derived fields for compatibility with other callers.

The original focused guild and battleboard test command ran 76 tests, with 61 passing and 15 guild tests failing. The source-data size and JSON parser probe are recorded in [data-migration.md](data-migration.md). The existing guild picker collects stopwatch timings for search, UI apply and initialization. These test and parser timings do not measure MAUI rendering, on-device memory allocations or end-to-end PDF export.
