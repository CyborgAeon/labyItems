# Account data isolation

Use the existing account workspace infrastructure rather than creating a new device-wide personal store. Multiple members share a device; signing in as guest/admin or a different member must not expose another member's data. Account ownership comes from the authenticated session, never from a player name, selected character, or a hard-coded email address.

## Data boundaries

| Data | Location and access |
| --- | --- |
| Public rules/reference catalogue | `account-vaults/public.db`, built from packaged assets and synchronizers. Safe for unauthenticated reference reads. Never seed it from a member database or the old shared database. |
| Member data | One encrypted `<account-key>.vault` per member under `account-vaults`. While unlocked, its working directory contains `laby.db`, calendar cache and generated files. Characters, wallet items and custom points-app definitions belong here. |
| Guest/admin fallback | A fresh temporary workspace seeded from public data. It is discarded on close, does not restore member vaults, and cannot access member points apps or the calendar. |
| Unowned legacy data | Encrypted `legacy.vault`; deliberately inaccessible until explicitly assigned to an account. Do not claim it for the first member who logs in or merge it into public data. |
| Member profile | `AccountProfileCache`, backed by platform secure storage, holds profiles for multiple credentials. Consume the current profile through `LabyrintheSession.Shared.Account`; do not expose the whole cache in UI or make profile fields editable. |

`AccountWorkspace.AccountKey(email)` hashes the trimmed, lowercase email. This is an identifier, not encryption or proof of login. Vaults use AES-GCM and separate keys obtained through platform secure storage by `AccountStorageCoordinator`. Decrypted working files exist during the active session; do not describe this as protection against a compromised device or copies exported outside the app.

## Where to obtain data

Paths below are relative to the repository root. Read the implementation relevant to the change; do not duplicate its initialization or key management.

- [AccountStorageCoordinator](../../../labyItems/Services/AccountStorageCoordinator.cs) installs providers, prepares the clean public catalogue, archives legacy data, recovers interrupted workspaces, and resets account-sensitive caches.
- [AccountWorkspace](../../../labyItems/Services/AccountWorkspace.cs) owns unlock, validation, checkpointing, encryption and close. `RequireDirectory()` and `RequireDatabase()` reject a missing, changed or stale session. `RequireMemberKey()` and `RequireMemberDatabase()` additionally reject guest/admin.
- [AccountDataAccess](../../../labyItems/Services/AccountDataAccess.cs) exposes the active workspace, write leases and generated-file directory provider. Production initialization must precede personal data access; its null-workspace fallback exists for isolated tests, not authorization.
- [ServiceHelper](../../../labyItems/Services/ServiceHelper.cs) routes reference reads to the active workspace database, or the public catalogue when no workspace is unlocked. This permits standard reference browsing; it is not a gate for personal writes.
- [LiteDbService](../../../labyItems/Services/LiteDbService.cs) routes character/wallet storage through `PersonalDatabasePathProvider`, installed as `workspace.RequireDatabase`.
- [LabyrintheSession](../../../labyItems/Services/LabyrintheSession.cs) supplies the authenticated email, current account profile, session version and authenticated HTTP requests.
- [WorkspaceCalendarEventCache](../../../labyItems/Services/WorkspaceCalendarEventCache.cs) wraps the calendar cache inside the owning workspace and validates the requested account before and after asynchronous work.

For a new personal file, obtain its directory from the workspace. For an export generated by existing document services, use `AccountDataAccess.CacheDirectoryProvider`. Do not persist member data directly under shared `FileSystem.AppDataDirectory`, shared cache directories or unscoped preferences. A personal record's display name is not an ownership boundary.

Use `AccountDataAccess.BeginWrite()` around synchronous database mutations, disposing database connections before the lease ends. It serializes against workspace close and checkpoints the encrypted vault. Use `workspace.BeginRead()` when a synchronous operation must hold a stable workspace. These leases use `Monitor`: do not hold one across `await` or dispose it on another thread. For asynchronous file operations, retain the originating identity/version, validate again after awaits, then checkpoint only the same active workspace.

Do not cache absolute workspace paths or open database handles across account switches. Points-app Microsoft.Data.Sqlite connections use `Pooling=False`: reusing a pooled handle after a working directory is removed and restored previously caused writes to target a stale file.

## Points apps and their documents

[PointsAppAccess](../../../labyItems/Services/PointsAppAccess.cs) and [NonStandardContentService](../../../labyItems/Services/NonStandardContentService.cs) are the access layer for custom abilities, spells, miracles, evocations, neuronics, classes and races. Their contracts live in `labyItems/Models/NonStandard`.

- Capture `PointsAppAccess.CurrentOwnerKey` when an editor opens. Supply it as `NonStandardSaveRequest.OwnerAccountKey`; the save validates it against the active member and stamps canonical `ownerAccountKey` into stored JSON. Never substitute the currently logged-in owner at save time for an editor opened by someone else.
- Document uploads pass the captured owner to `SaveDocumentLinkAsync`. Returned wallet entries and document links carry `OwnerAccountKey`; retain it when passing them between pages.
- Before opening a document, use `RequireDocumentAccess`/`CanAccessDocument`. These verify both the member and the stored reference fields against the owner's current database. A retained DTO, URI, filename or document ID alone is insufficient. Preserve native-platform checks immediately before launch, including after asynchronous preparation.
- Global search applies `PointsAppAccess.CanSeeDefinition` before sorting, pagination and result counts. Include `DataJson` in every relevant query result so filtering can inspect ownership. Supplemental class/race results need the same check. Public definitions remain visible.
- Older unstamped custom rows are accepted only inside their already-isolated member database. This compatibility behavior does not authorize reading the unowned legacy archive.

Do not rely solely on hiding a menu or search result. Enforce membership at the database/document service boundary as well.

## Account switches, pending operations and caches

Use [AccountNavigation.SwitchAsync](../../../labyItems/Services/AccountNavigation.cs), which replaces the navigation tree, invalidates pending operations, seals and closes the workspace, logs out, and resets caches before showing login. If sealing fails, former pages remain inaccessible. Do not implement a switch by changing a label, email or root page alone.

For asynchronous reads/searches, capture `session.Version` before starting and call `RequireVersion(version)` before using the result. Publish shared cache/UI state through `session.Publish(version, action)` where a check and publication must be atomic. Pass the originating version to session HTTP APIs that accept `expectedVersion`; old requests must not acquire the next member's cookies or publish into their UI.

Every new static cache containing database-derived content needs account-aware invalidation in `AccountStorageCoordinator.ResetCaches` or an equivalent versioned design. This includes rule lookups because the active database also contains private custom definitions. Do not let a pending load repopulate a cleared cache after a switch.

Current shared-device login requires credentials; device-wide biometric identity cannot distinguish members sharing a phone. Do not restore automatic biometric access to another member's saved credentials as an incidental change.

## Verification for changes to the boundary

Use [AccountWorkspaceTests](../../../tests/labyItems.Tests/AccountWorkspaceTests.cs) and [PointsAppOwnershipTests](../../../tests/labyItems.Tests/PointsAppOwnershipTests.cs) as existing fixtures. Meaningful checks cover owner A saving and reopening, member B seeing none of A's data, guest/admin denial, stale editors and delayed results after switching, and retained/altered document references being rejected. Preserve the separate legacy archive.

Run tests appropriate to the change and compile affected platform code when document opening or UI callers change. Existing missing-font failures in `ScrollDocumentServiceTests` are unrelated; report exclusions explicitly rather than describing a filtered run as the entire suite.
